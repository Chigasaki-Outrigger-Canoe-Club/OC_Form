# OC_Form

アウトリガーカヌーのフォーム解析システム。動画から骨格を推定し、将来的に Concept2 PM5 の実測データと同期して、フォームと出力の関係を解析する。

公開URL：https://chigasaki-outrigger-canoe-club.github.io/OC_Form/

## 使い方
画面は上から「選手 → 動画と3Dモデル → フォームの改善点 → 過去データ読み出し → ストローク」の順。

1. **選手**を選ぶ（「＋追加」で登録）。身長・体重・パドル寸法は選手ごとにブラウザ内へ自動保存
2. **動画と3Dモデル**：方向（前・左・右・後ろ）のタブで動画を選択（fpsは動画から自動取得。読めないときだけ入力欄が出る）
3. メモを入れて「**解析 → 3Dモデル → 保存**」を押す。未解析の全方向を解析し、統合3Dモデルと改善点を作り、保存する（解析済みの方向はそのまま使う。中止・失敗したときは保存しない）
4. 「動画」「3Dモデル」のボタンで表示を切り替える（3Dは再生位置の位相に合わせて動く）
5. **フォームの改善点**を確認する
6. **過去データ読み出し**：一覧（練習日・メモ）の行を押すと表示。JSONの書き出し・読み込み（GitHubに保存したファイルも読み込める）、CSVの書き出し
7. **ストローク**：自動検出の結果を必要なときだけ修正し、「修正を保存」

動画はブラウザ内でのみ処理する。初回のみMediaPipeのライブラリとモデルをCDNから取得する。GitHub保存をオンにした場合だけ、解析結果（動画以外）をGitHubに送る。

### 推奨ブラウザ
スマホで撮った動画（HEVC/H.265）は、**Chrome・Edge（Windows/Mac）またはSafari**で再生できる。ただしパソコンにHEVC対応（ハードウェア）がない場合は表示できない。その場合は画面に理由が表示されるので、カメラ設定をH.264にして撮影するか、H.264に変換する。

## 解析の考え方（推定値の扱い）
- **関節座標**：MediaPipeの推定値（`est`）。手動修正した点は `manual`。信頼度（visibility）0.5未満の点は薄く表示し、角度計算に使わない。
- **角度**：画像上の2D座標から計算した値。カメラの向きにより真の関節角度とは異なる。
- **ストロークの区切り**：低い方の手が最も高くなる時点（キャッチ直前付近）。キャッチの瞬間そのものではない。
- **3D骨格**：MediaPipeの worldLandmarks（腰の中心が原点、およそm）を、動画ごとに1つの回転で「X＝選手の左、Y＝上、Z＝選手の前」にそろえ、足の最も低い点の中央値を床とする。1台のカメラからの推定なので奥行きの精度は低い。
- **統合3Dモデル**：3本の動画は同時撮影ではないため三角測量はしない。各動画のストロークを0〜100%に正規化して漕ぐ側（左右）ごとに平均し（代表ストローク）、胴の長さで大きさをそろえ、同じ位相の点を方向ごとに重み付き平均する。重み＝信頼度 ×「軸の見やすさ」（カメラの奥行き方向の軸は 1−0.8＝0.2、画面に平行な軸は 1）。表示中の動画の位相に合わせて動く。「同じ漕ぎ方を繰り返している」と仮定した推定で、特定の1ストロークの再現ではない。
- **フォームのコメント**：統合モデルから体幹の前傾の幅、上体の回旋の幅、引きの途中の下の手の肘の角度・シャフトの左右の傾き、ストローク時間のばらつきを計算し、暫定の目安から外れたものを「改善候補」として表示する。目安は一般的な指導ポイントをもとにした値で未検証。
- **簡易パドル**：上の手がTグリップ（上端）を持ち、シャフトが両手を通ると仮定した推定値。ブレード面は前を向くと仮定。
- **漕ぐ側**：区切りと区切りの間で手が最も低い時点の「下の手」の側。ストロークごとに判定するため、パドルチェンジがあっても追従する。後方からの動画では左右の判定を誤ることがあるため確認が必要。

## データの保存場所
- 選手データ：ブラウザの localStorage
- セッション：ブラウザの IndexedDB（解析結果と動画は別に保存。動画1本で約60〜70MB）
- どちらもこのPCのこのブラウザ内だけ。ブラウザのデータを消去すると消える。別のブラウザやPCからは見えない
- 消える心配を減らすため、保存時にブラウザへ「自動で消さない」よう依頼している（許可されない場合もある）
- 削除：セッション一覧の「削除」。全部消す場合はブラウザの設定でこのサイトのデータを削除する
- GitHub（任意）：セッション欄の「GitHubにも自動保存する」をオンにすると、保存のたびに解析結果を `data` ブランチの `data/選手名/練習日_セッションID.json` に保存する（同じセッションは上書き）。動画は送らない。**このリポジトリは公開なので、保存したデータは誰でも見られる**（利用者が了承済み）。トークンは Fine-grained token（OC_Form の Contents を Read and write のみ）を使い、このブラウザ内にだけ保存する
- ブラウザ内の削除はGitHub上のファイルには反映されない。GitHub上のファイルは data ブランチから手動で削除する

## 既知の制約
- 骨格推定は動画を1フレームずつ送って行うため、40秒の動画で数分かかる。
- MP4以外の動画はfpsを読めないため手入力が必要。
- 実寸換算（パドル長による校正）は未実装（MVP 2）。
- 3D表示は仕様書ではThree.jsだが、開発環境からライブラリを取得・検証できないため、現在は依存なしのCanvas描画で実装している。骨格と線の表示には十分で、面の表現や重ね合わせが必要になった段階でThree.jsへの移行を検討する。

## テスト
```
npm test
```
- まとめて実行：骨格推定を模擬データに差し替えて、3方向の解析→統合→保存の流れ、選手・動画がないときの案内、2回目（全方向が解析済み）の上書き保存を確認
- GitHub保存：GitHub APIを模擬して、接続テスト・dataブランチの作成・新規保存・上書き（sha付き）・設定の保持・動画やblob URLが含まれないことを確認
- 自動テスト52件：過去データのファイル形式、GitHub保存（パス・Base64・接続テスト・ブランチ作成・上書き・エラー）、統合（位相そろえ・平均・軸の重み・誤差の低減・大きさそろえ）、フォームの指標とコメント、セッションの保存形式・要約・並び順、選手管理（追加・同名・更新・名前変更・削除・旧データ引き継ぎ・バックアップ）、3D座標の変換（カメラの向き5通り）、パドル推定、投影、圧縮形式の読み取り、時間・フレーム変換、角度、体幹の傾き、信頼度による除外、ストローク検出（一定ピッチ・パドルチェンジ・欠損あり）、MP4ヘッダ読み取り（30fps・25fps）、CSV・JSON出力

- 画面構成の変更後：骨格推定を模擬データに差し替えて、選手→3方向の動画→まとめて実行→3D表示への切り替え→改善点→過去データ一覧→JSON書き出し→別のブラウザで読み込み（選手の自動追加、動画なしでの3D再生）→過去データ表示中に新しい動画を選ぶと新しいデータになることを確認。HEVC動画を表示できない環境でメッセージが出ることを確認。3方向の模擬データ（パドルチェンジあり）で統合モデル・漕ぐ側の切り替え・方向の除外・コメント表示を確認。セッションの保存→ページを閉じて開き直し→開く・上書き・動画なしで開いて動画を選び直す・削除を確認
